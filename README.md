	Superstore Data Platform 
	
	Overview:
	This project builds a modern, end-to-end data platform on Databricks Serverless using the Medallion Architecture (Bronze → Silver → Gold), with automated CI/CD powered by Databricks Asset Bundles (DAB) and GitHub Actions.
	
	It demonstrates real-world data engineering practices including:
		•	Modular pipeline design
		•	Environment-based deployment (dev, qa, prod) 
		•	Git integration with branching strategy
		•	Semantic layer for analytics
		•	Feature engineering for ML use cases
	
	Architecture:
	Source → Bronze → Silver → Gold → →Semantic Layer → BI
										Gold → Features → ML

	Getting Started:
		A.	Setup and Installation 
			Prerequisites 
			•	Databricks Account: Make sure you have a Databricks workspace set up. 
			•	Databricks CLI v0.295.0: Ensure Databricks CLI is installed for deployment. 
			
			curl -fsSL https://raw.githubusercontent.com/databricks/setup-cli/v0.295.0/install.sh | sudo sh
			
			1.	Clone the repository 
			Clone this project into your local machine or Databricks workspace repos.
			git clone https://github.com/yourusername/superstore_data_platform.git
			cd superstore_data_platform
			
			3.	Install dependencies
				Install required Python dependencies: 
				•	databricks-cli 
				•	databricks-bundle for Databricks Asset Bundles (DAB) 
			
				pip install databricks-cli
				pip install git+https://github.com/databricks/databricks-bundle.git
			
			5.	Environment Variables
			Set up your Databricks secrets for DATABRICKS_HOST and DATABRICKS_TOKEN in GitHub Secrets to enable CI/CD pipeline deployments.
		
		B.	Deployment Process
			1. Manual Deployment 
				•	To manually deploy your code, use Databricks CLI or run the notebooks directly from Databricks UI. 
			2. CI/CD Deployment
				•	Push changes to GitHub and GitHub Actions will automatically trigger the appropriate pipeline: 
				•	dev branch → deploy to Dev environment. 
				•	qa branch → deploy to QA environment. 
				•	main branch → deploy to Prod environment.
				
			How to Trigger Deployment 
				1.	Push to Dev: 
					•	Push code to dev branch and GitHub Actions will deploy to the Dev environment. 
						git push origin dev
				2.	Push to QA: 
					•	Push code to qa branch and GitHub Actions will deploy to the QA environment. 
						git push origin qa
				3.	Push to Main: 
					•	Push code to main branch and GitHub Actions will deploy to the Production environment. 
						git push origin main
	
	After deployment, Databricks Jobs are automatically created with the _env suffix, and the bundle files appear in the workspace path defined in databricks.yml. Jobs can be executed immediately or scheduled as needed.
	
	Logs & Monitoring: 
	Logs for each environment and layer are automatically generated using superstore_logger.py, which logs the layer_run_id, master_run_id,layer, other status of each task. The logs are also stored in Databricks when jobs run and can be accessed for troubleshooting and monitoring.
			
	Challenges Faced:
	1.	Databricks CLI Version Issues: Faced issues with incorrect CLI version during CI/CD pipeline setup. Resolved by using the official Databricks CLI installer. 
	2.	GitHub Actions Permissions: Encountered permission issues with Personal Access Tokens (PAT). Fixed by adding the required workflow scope to the PAT.
